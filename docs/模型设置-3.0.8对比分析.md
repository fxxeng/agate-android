# 模型相关设置 · 3.0.8 对比分析

调研对象：上游项目 3.0.8（`agent2api`）与本项目 agate-android。
调研范围：模型管理页的设置项、内核契约、能力位语义、元数据来源。

---

## 一、3.0.8 的模型页整体结构

一个页面，**两种数据源**，同一套渲染：

| 数据源 | 取数 | 写入语义 |
|---|---|---|
| 内置家 | `GET /api/models/manage` → `{models, mappings, reasoningLevels}` | 逐条即时生效（点一下即存，无保存按钮、无草稿态） |
| 自定义家 | 目录缓存里该家的 records | **整表替换**，体验与内置家一致 |

左栏是提供商导航：`全部`（聚合视图）+ 各家（筛选视角）+ 自定义家分组。

## 二、模型表的 9 列（8 列数据 + 勾选）

| 列 | 内容 | 备注 |
|---|---|---|
| `check` | 全选/单选 | 唯一内容会变的表头 |
| **`model`** | 上游模型名 | |
| **`rate`** | 倍率 | |
| **`visibility`** | **可见性** | 「这个模型在官方客户端里是否会被展列；不展示的那些默认已关闭（含默认绑定）」 |
| **`source`** | 来源 | 上游目录 / models.dev / 手动 |
| **`budget`** | **上下文 / 输出** | 数字带虚线底 = 由 models.dev 补齐；**右上角小点 = 你手动覆盖过**；— = 未声明。点任意一格可改 |
| **`caps`** | 能力位徽章 | 工具 / 图片 / 视频 / 思考 |
| **`alias`** | 别名（映射） | chip 形式，带三元组 (alias, target, provider) |
| `act` | 操作（测试） | 两层弹窗 |

### 三态显示约定（很关键）

> 布尔能力：`true` 支持 / `false` 明确不支持 / **`null` = 未声明**（上游清单里就没这个键）
> 数值能力：数字 / `null` 未声明

**「未声明」与「不支持」必须分开显示** —— 混在一起用户会把「不知道」当成「不支持」照着抄。

能力弹窗里的完整文案：
- 未声明（内置家）：`上游未声明（下游会按不支持处理）`
- 未声明（自定义家）：`未填写（下游按未声明处理）`
- 已覆盖：`已覆盖：对下游声明 {value}`
- models.dev 补齐的项：**不能**说成「继承上游」（那是别家的数据）

### 「继承 / 覆盖」两态交互

| 类型 | 表达 |
|---|---|
| 数值（上下文 / 最大输出） | 输入框里是**覆盖值**，**留空 = 继承**（placeholder 显示上游值）；已覆盖的挂「恢复继承」 |
| 布尔（工具/图片/视频/思考） | **三档**分段选择：继承上游 / 支持 / 不支持 |

值的三态与后端一致：`null` = 清除覆盖/恢复继承、有值 = 覆盖。`capOverrides` 数组记录被覆盖过的键。

## 三、六个能力键（与内核 `core::capability::KEYS` 逐字一致）

| 键 | 类型 | 文案 | 短标签 |
|---|---|---|---|
| `maxInputTokens` | 数值 | 上下文窗口 | — |
| `maxOutputTokens` | 数值 | 最大输出 Token | — |
| `supportsToolCall` | 布尔 | 工具调用 | 工具 |
| `supportsImages` | 布尔 | 图片识别 | 图片 |
| `supportsVideo` | 布尔 | 视频识别 | 视频 |
| `supportsReasoning` | 布尔 | 支持思考 | 思考 |

## 四、思考等级（reasoning）

三级回落，不硬编码：

```
模型自己声明的档位（reasoningLevels）
  → 后端下发的通用表（model_rules::REASONING_LEVELS）
    → 本地兜底表
```

兜底档位：`off / none / minimal / low / medium / high / xhigh / max`

- 「自定义等级」的哨兵值是 `__custom__`（不是空串 —— 空串表示「不覆盖」，两者必须分开）
- 某条映射的等级按 **(alias, target, provider) 三元组**查，不另加平行数组

## 五、3.0.8 设置页的其他模型相关项

## 六、我们的实现现状

### 内核侧：**基本齐全**

| 项 | 状态 | 证据 |
|---|---|---|
| `capability.rs` 六键 | ✅ | `pub const KEYS: [&str; 6]`，`effective()` 计算生效值 |
| `capOverrides` 覆盖语义 | ✅ | `capability.rs` 有「生效值里被覆盖的键」 |
| `/api/models/manage` | ✅ | `GET` → `{models, mappings, reasoningLevels}` |
| 自定义家整表保存 | ✅ | `POST /api/custom-providers/models` |
| models.dev 元数据 | ✅ | `api/model_meta.rs`：`GET/PUT /api/models/metadata` + 立即刷新 |
| 六键字段真实使用 | ✅ | 各键在 7–22 个文件中出现 |

### 客户端侧：**差距明显**

| 项 | 3.0.8 | 我们 | 差距 |
|---|---|---|---|
| 页面结构 | 单页 = 左栏导航 + 模型表 + 3 弹窗 | 3 个独立页：`ModelsPage`(415) / `ModelCapsPage`(436) / `ModelMappingPage`(665) | 结构分家 |
| 模型表列 | **9 列**（含可见性/来源/上下文/能力/别名） | 只有名称、provider、id | **缺 5 列** |
| 可见性 | ✅ 独立列 + 说明 | ❌ 搜索无结果 | **缺** |
| 来源 | ✅ 上游/models.dev/手动 | ❌ | **缺** |
| 上下文/输出 | ✅ 表内可编辑 + 虚线底/小点标记 | 仅 `ModelCapsPage` 里编辑 | 无表格内联 |
| 能力徽章 | ✅ 表内 4 个小徽章 | ❌ 只能进弹窗 | **缺** |
| 别名 chip | ✅ 表内 chip + 三元组 + 映射开关 | 独立页 | 体验分家 |
| 三态显示 | ✅ 「未声明」与「不支持」分开 | ✅ **已做对**：`sourceLabel()` 返回「未声明 / 上游实测 / 社区库 / 用户改」，`—` 与 `关` 分开 | 一致 |
| 继承/覆盖 | ✅ 留空=继承 + 恢复继承 + 三档分段 | ✅ **已做对**：`BoolTriplet` 三档「跟随上游 / 开 / 关」；`capOverrides` 有「已覆盖 N」徽章；提交时 `null` = 恢复上游 | 一致 |
| 思考等级三级回落 | ✅ | ✅ **已做对**：用响应里的 `reasoningLevels`（内核 `model_rules::REASONING_LEVELS`），**刻意不在前端抄一份**避免漂移 | 一致 |

> 结论修正：P0 三项**不需要改** —— 我们的 `ModelCapsPage` 已经把三态、覆盖语义、思考等级都做对了。
> 它甚至比 3.0.8 多一层信息：每项都显示「当前值 · 来源：上游实测 / 社区库 / 用户改」，
> 把「这个数是谁说的」直接写在界面上（3.0.8 是靠虚线底 + 小点两个视觉符号表达）。
| 测试弹窗 | ✅ 两层（门禁判定 + 弹窗） | 有 `MODEL_SPEEDTEST` 路由 | 已有 |

## 七、建议的推进顺序

按「价值 / 成本」排：

### ~~P0~~ —— 已确认无需改动

三项语义（三态显示 / 继承覆盖 / 思考等级）我们**都已经实现且正确**，并且能力页还多给了
「当前值 · 来源」这一层信息。这一层是核心，不用动。

### P1 —— 补齐模型的「一眼可见」信息（真正的差距所在）

4. **模型表加列**：可见性 / 来源 / 上下文·输出 / 能力徽章。数据内核都有，只是界面没渲染。
5. **覆盖标记**：上下文/输出值加「虚线底 = 元数据补的」「小点 = 我覆盖过」——这两个视觉语言是 3.0.8 刻意设计的，回答「这个数到底是谁说的」。

### P2 —— 结构收敛（改动大，需先讨论）

6. **三页合一**：`ModelsPage` + `ModelCapsPage` + `ModelMappingPage` → 单页（左栏家导航 + 模型表 + 弹窗）。理由同 3.0.8：映射、能力都是**某个模型的属性**，拆成三个页面后用户要为同一个模型在三个页面间跳。

### P3 —— 设置页的模型相关项

7. **提示词模式三档**（passthrough / custom / append）—— 内核是否已支持需确认。
8. **AI 助手面板**（对话模型 / 系统提示词 / 工具勾选）。

## 八、需要你定的两件事

1. **P2 三页合一做不做？** 这是最大的一处结构差异（3 个页面 ≈1516 行 → 单页），也最费工。
2. **P1 的表格加列**先做哪几列？我建议按这个顺序：
   - ① **上下文 / 输出**（数据已在 `/api/models/manage` 里，只是模型表没渲染）
   - ② **能力徽章**（工具/图片/视频/思考四个小徽章，一眼扫完）
   - ③ **可见性**（这一列关系到「官方客户端会不会展列」，语义要确认）
   - ④ 来源、别名 chip（别名已有独立页，最后做）

> 说明：P0 属于「把已有能力做对」，我可以直接改；P1/P2 涉及界面布局与信息层级，按约定会先出方案再动手。
