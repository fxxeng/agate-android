# 模型清单「默认启用」种子：缺陷排查与修复记录

日期：2026-10-28
触发：用户截图显示模型页只有 15 个模型，与 WorkBuddy 桌面端不一致
结论：`seed_default_enabled` 的「空数组白名单」语义陷阱，已修复；四家提供商已横向排查

---

## 一、现象与复算

截图：15 个模型，其中 14 个带倍率标签（`0.18x` / `0.71x` / `0.51x` …），另有一个 `auto`。

复算链（与截图逐项吻合）：

| 阶段 | 发生了什么 | 结果 |
|---|---|---|
| 冷启动 | 内置清单过准入 = 23 条 → 种子按 `whitelist=&[]` 处理 | 23 条**全部被禁用**，同时记账 23 条 `seeded` |
| 紧接着 | `migrate_enable_vetted` 跑（v1 全局标记） | 23 条全部恢复，**标记被烧掉** |
| 远程刷新 | 上游下发 39 条 | 其中 14 条已在 `seeded`（= 内置 ∩ 远程）→ 保持启用；另 25 条是全新 id → **又被禁用**，而标记已烧，无人纠偏 |
| 最终 | `14 + auto` | **15 个** |

`auto` 只存在于 `builtin_models()`，上游 66 条里没有它 —— 它出现在界面上本身就证明混入了内置清单。

**倍率是远程真值，不是内置写死**：截图 14 个倍率与上游 2026-10-27 的真实值逐一吻合，而 `model_meta` 不补 `credits`，所以倍率只可能来自远程。这条否证了「数据不是远程」的假设。

## 二、根因

### 2.1 `&[]` 的语义与调用方的意图正好相反

```rust
// 修复前
fn seed_default_enabled(provider: &str, label: &str, whitelist: &[&str], ids: &[String]) {
    ...
    let default_enabled = whitelist.iter().any(|name| name.eq_ignore_ascii_case(id));
    if !default_enabled && !rules.is_disabled(provider, id) {
        set_membership(&mut rules.disabled, Some(provider), id, true);  // 禁用
    }
}
```

传 `&[]` 时 `any` **恒假** → `!default_enabled` 恒真 → **每条都禁用**。
而 `workbuddy.rs` 当时的注释写的是「默认一律启用」。

这个 bug 是**「修复」自己引入的**：`ed051fe`（2026-10-27「修『拉到 40 个只显示 2 个』」）是 `2ff4c2e` 的祖先，且交付 APK 的内核二进制里能搜到 `migration:enable-vetted-v1` 字符串 —— 证明那次改动确实随包发出去了。

### 2.2 `default_enabled` 同时是两道门禁

`catalog/view.rs` 的 `public_builtin_items` → `builtin_target`（`catalog/routing.rs:39-45`）：

```rust
if let Some(id) = entry_id_in_manifest(manifest, requested) {
    if rules.default_enabled(provider, &id) {   // ← 唯一门禁
        return Some(WireTarget { ... });
    }
}
```

不满足就 `return None` —— 于是「被禁用的模型」不是**隐藏在列表里**，而是**根本不出现**。这是架构层面的语义混淆：一个本该表达「默认值」的字段，承担了「路由可用性」的职责。

### 2.3 v1 迁移标记是全局的

`migration:enable-vetted-v1` 不带 provider。WorkBuddy 拆家后是两个 provider（`workbuddy` / `workbuddy-intl`）：

- 先跑的那家烧掉标记；
- 后跑的那家（国际版）**永远得不到纠偏**。

### 2.4 标记烧得太早

v1 在执行时机上认的是「冷启动那一刻手里的清单」。如果那时只有内置清单（23 条），就等于用**一份残缺清单**宣布「该纠的都纠了」；等远程 39 条落地，新增的 25 条没人管。

## 三、修复

四处改动，全部在 `agate-server/src/server/core/model_rules/` 与两处调用点。

### 3.1 签名改成 `Option`，把两种语义显式分开

```rust
fn seed_default_enabled(
    provider: &str,
    label: &str,
    whitelist: Option<&[&str]>,   // ← 原为 &[&str]
    ids: &[String],
) -> Option<String> {
    ...
    rules.seeded.push(format!("{provider}:{id}"));
    // `None` = 这个家不按白名单判默认状态（只记账）
    let Some(whitelist) = whitelist else { continue };
    ...
}
```

- `Some(list)` —— 不在 `list` 里默认**禁用**（Qoder 用这个，语义不变）
- `None` —— **一律不禁用**，只记账（WorkBuddy 改用它，替代原来的 `&[]`）

`None` 是一条**没有分支**的路径：不写 `disabled`，自然也不会有需要纠偏的存量。

### 3.2 WorkBuddy 传 `None`

```rust
let _ = WORKBUDDY_DEFAULT_ENABLED;   // 保留常量为历史注记
let summary = super::seed_default_enabled(provider, &label, None, ids);
```

`WORKBUDDY_DEFAULT_ENABLED` 常量保留但显式忽略，并在注释里写明「别改回 `&[]`」。

### 3.3 迁移标记改 v2 并按 provider 分

```rust
let mark = format!("migration:enable-vetted-v2:{provider}");
```

v1 的老标记不再被检查 —— 它表达的那次纠偏已被 v2 覆盖，两者不是「跑过就不跑」的关系。

### 3.4 新增 `authoritative`：标记只能在远程权威清单上烧

```rust
fn migrate_enable_vetted(provider: &str, ids: &[String], authoritative: bool) -> Option<String> {
    if !authoritative {
        return None;   // 连 current() 都不读
    }
    ...
}
```

两个调用点：

| 调用点 | `authoritative` | 理由 |
|---|---|---|
| `core/models/mod.rs:702`（`apply_remote`） | `true` | 这就是远程清单落地的位置 |
| `providers/adapter.rs:1354`（`seed_current_workbuddy_defaults`） | `catalog.remote_refreshed()` | 手里可能是内置（false）也可能是缓存（true） |

**为什么非权威时「整段跳过」而不是「只纠不烧」**：不烧标记意味着这条路径每次都跑，而纠偏是「解除这批 id 的全部禁用」—— 用户在管理页显式关掉的模型会在下一次启动被悄悄打开，反复覆盖明确意图，比一次性误开严重得多。

**缓存算权威是刻意的**：`initial_state` 把缓存恢复的清单置为 `remote_refreshed = true`。判据要的是「这份 id 集合来自远程目录」，不是「这一秒刚拉」。内置 23 条**不能**当判据 —— 它是本地写死的子集，永远比远程少。

## 四、四家提供商横向排查

| 提供商 | 种子函数 | 默认禁用策略 | 是否同类缺陷 |
|---|---|---|---|
| **WorkBuddy** | `seed_workbuddy_defaults` → `seed_default_enabled` | 原 `&[]`（实际全禁）→ 现 `None`（不禁） | **是，已修** |
| **Qoder** | `seed_qoder_defaults` → `seed_default_enabled` | `Some(QODER_DEFAULT_ENABLED)`，只放行 `Qwen3.8-Flash` | 不是同一 bug，见下 |
| **Raccoon** | `seed_raccoon_defaults`（独立实现） | 只禁用 `raccoon-<hex>` 内部模型 | 否 |
| **Cline** | `cline::adapter::seed_defaults` / `model_rules::cline` | 只建去前缀别名，不做启停 | 否 |

### Qoder 的判定

Qoder 16 条里只有 1 条默认启用（`Qwen3.8-Flash`），症状看起来一样「列表少」，但它**不是 `&[]` 那个 bug**：

- 它传的是 `Some(&["Qwen3.8-Flash"])`，`any` 判定正常工作，**白名单确实生效**；
- 代码里有书面理由（`QODER_DEFAULT_ENABLED` 的文档注释）：Qoder 目录里绝大多数条目是**套餐档位别名**（`Auto` / `Ultimate` / `Performance` / `Efficient` / `Sonus` / `Cantus`）或需高档套餐才可用的模型，默认全开会让对外模型列表凭空多出十几个没人点名的名字，**而且它们会参与 `/v1/models` 的同名认领，把别家真正在用的同名模型（如 `GLM-5.3` / `Kimi-K3`）挤掉**；
- 白名单里那个名字与 `fallback()` 静态清单**精确匹配**（`"Qwen3.8-Flash"`，第 83/106 行），不会因拼写差异导致全部被禁用。

**判定：有意设计，不是缺陷。** 唯一可讨论的是「只放行 1 个是否太少」—— 但这属于产品取舍，不属于本次 bug 修复范围。若将来要放宽，判据应该是「这个模型在当前套餐下真的可用」，而静态清单里的 `enabled` 字段源码自己承认只是「免费档通常可用」的**猜测值**，不足以当依据。

### 另外两个相关发现（不在本次修复范围，记录备查）

1. **`visibility` 是死字段**：`core/models/mod.rs:665-671` 在 `apply_remote` 里写 `visibility: shown|hidden`，全仓 grep **零消费方**。管理页用 `enabled` 显示状态，`/v1/models` 用 `builtin_target` 门禁，这个键谁都不读。
2. **UA 版本号严重过期**：`endpoints.rs` 的 `WORKBUDDY_CLIENT_VERSION = "5.5.4"` / `WORKBUDDY_CLI_VERSION = "2.137.1"`，而本机官方客户端 `/c/Program Files/WorkBuddyAI/version` = `37.10.3-24`，上游配置 `genieVersion = 5.9.3`。`endpoints.rs:65` 的注释明确写：UA 里缺 `CLI/<版本>` 段时 `/v3/config` 只下发**旧版兼容清单（37 个，无 v4.1/5.3/hy4/modelPromotions）**，带上才下发完整清单（51 个）。这是**另一个独立问题**（影响清单覆盖面），不是本次 15 个的成因 —— 但值得单独处理。

## 六、踩过的推理错误（如实记录）

1. **最初把根因归给「UA 版本号过期」**。后来逐条核对倍率发现全部吻合（说明拿到的是远程真值），再精确复算出 39→15 才定位到 `&[]`。UA 过期是另一个独立问题。
2. **第一版加固写成「非权威只纠偏不烧标记」**。写到一半意识到这更糟：不烧标记 → 每次都跑 → 反复打开用户显式关掉的模型。改成整段跳过，并把判断提到读规则之前（否则「不动」是假的）。
