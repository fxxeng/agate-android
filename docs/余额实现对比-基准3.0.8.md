## 3. 页面口径：为什么「优选临近到期」

同一家可能同时有几份额度，到期时间各不相同（workbuddy 的包、zcode 的套餐、qoder 的资源包、trae 的权益包都是这样）。
只显示「总量」会掩盖一件事：**总量很多，但大部分下个月就作废**。

因此额度中心按下面的规则取数（`QuotaCenterPage.extractExpiry`）：

1. **递归扫描** usage JSON，凡对象上同时能读到「剩余」与「到期」就记为一个候选桶；
   - 剩余键：`left / remain / remaining / balance / available / credits / points / totalPoint`
   - 到期键：`expireAt / expiresAt / expiredAt / endAt / endTime / validEndTime / periodEnd / period_end / endsAt / expireTime`
2. **只考虑还有数的桶**（`> 0`）；
3. 在其中有**未来到期**时间的里面取**最早**的一个 → 这就是「最近到期」；
4. 时间单位自动归一（`< 1e11` 视为秒，否则毫秒；字符串按 ISO 解析）；
5. 该家**没有任何桶级到期**时，才退回用 `subscription.expireAt`（并如实写「订阅到期」）。

展示与排序：

| 剩余天数 | 徽章 | 文案 |
|---|---|---|
| ≤ 3 天 | 红色 `N天到期` | 副行 `… · N 天后到期` |
| ≤ 7 天 | 橙色 `N天到期` | 同上 |
| ≤ 30 天 | 绿色百分比徽章 | 副行 `… · N 天后到期` |
| > 30 天 | 绿色百分比徽章 | 副行 `… · M月D日到期` |
| 已过期 | — | `已过期`（且不参与「最近到期」选取） |

排序优先级（组间与组内一致）：**最近到期 → 低余额（≤20%）→ 查询失败 → 账号数**。

## 4. 仍未对齐的一处：`chatglm`

3.0.8 有 `providers/chatglm/`（`balance.rs` 里 5 处到期、2 个桶），本仓库没有这一家 —— 不是余额没接，是**整个 provider 未移植**。
补齐它需要：`providers/chatglm/{mod,adapter,endpoints,credentials,login,balance}.rs` + `ProviderKind` 变体 + 登录 UI 注册，属于「新增一家」的完整工作量，建议单独立项。
