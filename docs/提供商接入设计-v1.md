# 提供商接入设计（v1 · 以核实事实为准）

> 基线：`agate-server` 内核源码（`core/login/*`、`api/session.rs`、`api/accounts.rs`、`core/account_store/*`）
> 说明：设计稿 v44 只给到大体框架，未逐页细化；本文以**内核可验证行为**为唯一事实来源。

---

## 1. 通道定义（6 类）

| 代号 | 通道 | 完成判定的承接方 | 系统浏览器可用 |
|---|---|---|---|
| `EMBEDDED` | 内嵌 WebView | 壳侧窗口 + 内核 | — |
| `EXTERNAL` | 系统浏览器 | 内核（轮询或 loopback） | 是 |
| `DEVICE_CODE` | 设备码授权 | 内核轮询设备令牌 | 是（与 EXTERNAL 同一实现，仅多显示 code） |
| `SMS` | 手机验证码 | 内核直连上游 | 否 |
| `PASTE` | 粘贴凭证 | 内核校验落库 | 否 |
| `IMPORT_FILE` | 导入凭证文件 | 内核解析文件落库 | 否 |
| `IMPORT_DESKTOP` | 桌面登录态实时读取 | 内核读本机固定路径 | **Android 隐藏** |

判定依据（源码）：
- 轮询类：`auth/token`、设备令牌、CLI `init`+轮询、服务端中介轮询 → 浏览器在哪登录都行 → `EXTERNAL` 可用
- loopback 类：回调落到 `127.0.0.1:<port>`，系统浏览器同样能回环 → `EXTERNAL` 可用
- 壳侧回调类：自定义协议或需壳把结果 POST 回内核 → **只能 `EMBEDDED`**
- `IMPORT_DESKTOP` 建的是「转发时实时读本机路径」的账号，手机上路径不存在 → **必须隐藏**

## 3. 数据模型

```kotlin
enum class AuthChannel { EMBEDDED, EXTERNAL, DEVICE_CODE, SMS, PASTE, IMPORT_FILE, IMPORT_DESKTOP }

data class ProviderPreset(
    val id: String,
    val label: String,
    val desc: String,
    val channels: List<AuthChannel>,   // 替代原 kind；顺序即 UI 顺序
    val pasteHint: String? = null,     // PASTE 通道的输入提示
    val pasteSecondaryHint: String? = null,
    val supportsCheckin: Boolean = false,  // 能力标签，不放通道
)
```

UI 展示规则：
- 通道 chips 只渲染 `channels` 中非 `IMPORT_DESKTOP` 的项
- 默认选中 = `channels` 第一项（EMBEDDED 优先）
- `DEVICE_CODE` 若同时存在 `EXTERNAL`，合并为一个「浏览器授权」入口，并在页面显示设备码

## 5. 各通道交互

### 5.1 EMBEDDED
按钮「开始网页登录」→ 弹 `AuthWebViewSheet` → 授权完成或拦截回调 → 成功回列表。

### 5.2 EXTERNAL / DEVICE_CODE
```
[在浏览器中打开]
  → POST /api/session/login/start {provider, mode:"external"}
  → Intent.ACTION_VIEW(authUrl)
  → 页面切「等待授权 · 已等待 mm:ss」[取消]
  → 每 2s GET /api/session/login/wait?state=…  （onResume 也补一次）
  → success → 落账号、回列表；failed → 显示原因；取消 → POST /cancel
```
DEVICE_CODE 额外显示：设备码文本 + 授权页链接（便于复制到官网粘贴）。

### 5.3 SMS
手机号 → 发码（60s 倒计时）→ 验证码 + 备注名 → 登录。

### 5.4 PASTE
按家定制的输入框（主/次）+ 备注名 → `POST /api/accounts`。

### 5.5 IMPORT_FILE
`ACTION_OPEN_DOCUMENT` 选文件 → 读原始字节：
- 文本 JSON → `authFileContent`
- 二进制（kuku SQLite）→ `authFileB64`
附带 `authFileName` → `POST /api/accounts`。
错误按内核文案透传（带文件名）。

## 7. API 契约

| 场景 | 端点 | Body |
|---|---|---|
| 内嵌/浏览器发起 | `POST /api/session/login/start` | `{provider, mode?}` → `{state, authUrl, edition, provider}` |
| 轮询 | `GET /api/session/login/wait?state=` | — → `{state, ...}` |
| 取消 | `POST /api/session/login/cancel` | `{state}` |
| 壳侧回调 | `POST /api/session/login/callback` | `{state, callbackUrl}` |
| 验证码 | `POST /api/session/login/sms/send` · `/sms/verify` | `{phone, provider}` / `{phone, code, name?, provider}` |
| 粘贴/文件/桌面 | `POST /api/accounts` | `{provider, apiKey/token/cookie/refreshToken…, name?, noAuth?, authFileContent?, authFileB64?, authFileName?, importDesktop?}` |
| 自定义家 | `POST /api/custom-providers` | `{name, baseUrl, apiKey|noAuth, protocol, balanceScheme?}` |

## 8. 边界与不做

- `IMPORT_DESKTOP` 在 Android 一律不出现
- `raccoon` / `catpaw` / `kuku` / `orcaterm` 不提供「浏览器登录」
- 不展示内核没有的能力：倍率区间以外的策略覆盖、凭证续期、限流明细
- 本期不做：25 张预置中转卡、扫码直传、WebDAV 备份

## 9. 核实结论（原待确认项，已全部查证）

1. **`monkeycode`**：内核 `supports_web_login = false`（上游要 go-cap 验证码 / 百智云 SCaptcha + 短信，网关只接「粘贴 session」）。→ **只有 PASTE**，不显示内嵌/浏览器。
2. **`antigravity`**：`supports_web_login = true`，`build_login_url` 本地拼授权地址、回调落 `http://localhost:{port}/oauth-callback` → **EMBEDDED + EXTERNAL 都可用**，另有 PASTE（refresh token）。
3. **`workbuddy`**：`add_account` 接受嵌套 `{auth:{accessToken,refreshToken,expiresAt},account:{uid,nickname}}`（官方客户端文件形态）与扁平 `{accessToken,refreshToken,uid}`；**uid 必填**，否则 400「缺少 uid」。→ **PASTE 可用**（粘贴整份 auth.json 即可）。
4. 额外核实：**`codearts` 的网页登录是有的**（`core/login/codearts.rs` + `/oauth/callback`）；`add_account` 注释里的「DPoP+PKCE 后续切片」指的是**手动粘贴侧**，不是登录侧 → 通道为 EMBEDDED + EXTERNAL + PASTE。
5. 额外核实：**`accio` 不提供 `importDesktop`**（桌面态在 Electron 加密区，内核明确拒绝），矩阵已修正。
