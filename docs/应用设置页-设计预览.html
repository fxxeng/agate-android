应用设置 · 设计预览

十组手风琴 · 面板对齐 v44 的 sub-appsettings，字段与范围逐条对齐内核端点

这一版只做内核真有端点的项。v44 里有、但内核没接口的（监听端口 / 无 Key 调用 / 忽略电池优化 / 自动更新间隔） 不放进这一页 —— 放进去就是点了没反应的死按钮。理由逐条列在文末「取舍」表里。

① 折叠态：一行一个现状

每组标题右侧固定一行当前值摘要（从内核读回来的真实值，不是写死的文案）。 这样不展开也能判断现状 —— 设置页最常被打开的理由是「我现在是多少」，不是「我要改」。

⑧ 交互规则（实现时的统一约定）

场景做法理由
首屏加载 一次读全 10 组（并发），任一失败只让该组显示「读取失败 + 重试」，不整页报错 十组是十条独立端点，一组挂了不该拖死整页
开关 点击即保存；保存中用「禁用 + 轻微透明」，失败回弹并把原因挂在开关下方 开关停在错误位置（显示开了其实没开）比报错严重得多
数字 弹层编辑单项，本地校验范围，保存只提交这一项 内核是整单校验：一项越界整组不落盘，本地先挡能省一次往返
保存响应 直接用 PUT 响应回填界面，不再 GET 一次 内核契约就是「返回生效后的全量值」，多读一次只会引入时序差
折叠摘要 每组副标题显示内核读回来的当前值（不是写死文案） 设置页最高频的问题是「我现在是多少」
危险动作 清除 Key / 恢复备份 / 清空正文：二次确认，且复述会丢什么（带具体数字） 「不可撤销」四个字不构成信息，具体数字才构成
只读项 明确标 只读 并给一句「要改去哪」 可点的灰块与不可点的灰块必须能区分，否则用户会反复点
空态 available:false 显示「库不可用」而不是一排 0 0 与「不知道」是两件事

⑨ 取舍：v44 有、这一版不做

v44 的项不做 / 改做的理由
监听端口 端口在本壳由 GatewayPrefs.port + 前台服务持有，改它要重启服务；这一页放输入框会与「网关控制」页重复。留在网关控制页。
无 Key 调用 / 同时监听局域网 本壳是 loopback 免鉴权形态，局域网开关在网关控制页已有。放两份会造出两个真相。
零宽空格脱敏（补充层） 已改为要做（本轮实现）。原先判断「八条端点已删除、没有端点就没有开关」只对了一半： 删掉的是词表管理那一整套（远程同步 / 作用角色 / 作用提供商 / 命中统计）， 而「用户自定义词 + 零宽空格打断」这个能力本身是可以重做的 —— 它补的正是内置规则集的短板 （规则集封闭、随版本走；词表开放、随用户走）。

实现：内核新增 sanitizeZwspWords 配置键 + GET/PUT /api/zwsp + core::sanitize 里的 insert_zwsp 层（跑在规则集之后， 因为规则集的改写要求原文完整出现）；壳侧 SettingsOps.zwspWords/saveZwspWords + 设置页「零宽空格脱敏」一组。

两点保留：① 它对纯数字串无效（上游会归一化），数字类指纹仍归内置规则集做字面改写； ② 已插入过零宽空格的位置不会重复插入 —— 否则多轮对话里每条历史消息每次出站都会多一个。
账号级限速（抖动 / 间隔） 内核无对应配置键。要做是内核改动，不在本页范围。
前台服务常驻 / 忽略电池优化 / 签到通知 属 Android 壳层能力，跟着「任务中心 → 定时签到」与系统设置走，不塞进网关设置。
跨端迁移（JSON 导入导出） 已有「备份与恢复（整库 SQL）」覆盖同一目标，且更完整。两套导入只会让用户分不清该用哪套。
升级前自动快照 / 数据结构升级 Android 无桌面端历史数据，/api/upgrade 恒为「无需升级」。做出来就是一个永远显示已完成的卡片。
检查更新 / beta 通道 / 更新间隔 /api/update/* 取的是桌面二进制。Android 的更新走 CI 产出的 APK，需要另一条链路 —— 单独一期做，先不放假按钮。
关于 → 接入文档 本轮先给「复制配置示例」（BaseURL + Key 拼成一段可直接贴进客户端的 JSON），比跳外部网页更实用。

⑩ 数据层已就绪

SettingsOps.kt（539 行）已写完并编译通过，界面只需调用。字段范围逐条对齐内核：

  • 超时四项：1–3600 秒，默认 30 / 300 / 300 / 300
