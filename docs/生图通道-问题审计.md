## 0. 一句话结论

生图这条链在**正确性**上是干净的（没有 unwrap、没有无界内存、没有鉴权漏洞），
问题集中在**「出错时说不清原因」**——最典型的是：当网关 Key 不允许任何能用
生图的家时，接口会说「这个模型没有生图通道，请换一个模型」，而真相是
「这把 Key 不允许这家」。用户会去换模型、重配账号，折腾一圈回到原点。

## 1. 中危：Key 不允许某家时，报的是「模型没有通道」  ✅ 已修

### 证据

`api/images.rs` 的 `resolve_model` 尾部：

```rust
let candidates = providers::images::operation_providers(&requested, operation);
if !candidates.iter().any(|provider| key_scope::allows_provider(scope, provider)) {
    return Err(GatewayError::bad_request(
        providers::images::unsupported_message(&requested, operation),  // ← 归因错了
    ).with_code(operation.unsupported_code()));
}
```

`operation_providers()` **只看能力位**（`kind=image` + `supports_image_*`），
不看 Key。所以「`candidates` 非空、但全被 Key 排除」这个分支里，
`unsupported_message()` 输出的是：

> 模型 'X' 没有可用的图片生成通道：目录里有这家（loomy），但它没有声明这类能力，
> 或它的自定义提供商尚未支持生图。请换一个图片生成模型（kind=image）

而后半句（「目录里有这家」）**恰好证明前提是假的**：这家声明了能力，
真正拦路的是 Key 的 provider 白名单。

### 影响面

任何使用「按 provider 限定 Key」的部署（这是网关的多租户主用法）。症状：
- 用户按提示换模型 → 换到任何一家都被同一把 Key 挡住 → 死循环；
- 管理页看目录一切正常（`/v1/models` 按 Key 过滤，但这家真有图）

### 修法（已落地）

拆成两个函数，判据也拆开：

```rust
// 能力问题 → 该换模型 / 更新目录
if candidates.is_empty() { … unsupported_message(…) }

// 权限问题 → 该改 Key 的允许列表（点名哪几家）
if !candidates.iter().any(|p| allows_provider(scope, p)) {
    … key_scope_message(&requested, operation, &candidates)
      .with_code("key_scope_excluded")
}
```

`key_scope_message` 输出：「模型 'X' 的图片生成通道在（loomy、raccoon），但这把
网关 Key 不允许其中任何一家：请在 Key 设置里放开上述家，或改用另一把 Key」。
错误码也分开了（`key_scope_excluded` vs 原来的 `image_generation_required`）。

新增 3 条测试钉住两句话不可互换（其中一条专门断言「权限那几句不能出现
『换一个图片生成模型』」）。

## 2. 中危：客户端取图无响应体上限  ✅ 已修

### 证据

`ui/components/AgateRemoteImage.kt::fetch`：

```kotlin
client.newCall(...).execute().use { response ->
    if (!response.isSuccessful) null else response.body?.bytes()   // ← 无上限
}
```

`content://` 分支同样是 `openInputStream(uri).readBytes()`。

内核自己发的链接有 `no-store` 且图已归一化，风险低；但**参考图来自相册**，
用户选一张 50 MP 的图就会把整个文件读进内存再解码。`decodeSampled` 的
`inJustDecodeBounds` 只省解码内存，**不省读字节的内存**。

### 修法（已落地）

两种来源走**同一段带界读取**（`boundedRead`），上限 10 MiB：

```kotlin
// 网络侧先看 Content-Length：超限连流都不开始读，省一次传输
if (body == null || body.contentLength() > MAX_IMAGE_BYTES) null
else body.byteStream().use { boundedRead(it) }
```

`boundedRead` 边读边计数，超限直接返回 `null` 走失败态。顺带把原来
`use { }` 块里的 `return null` 改成嵌套 `if` 表达式 —— `use` 是 inline 函数，
块里 `return` 会直接跳出 `fetch`（行为对，但读代码的人容易误判成「跳过这次响应」）。

新增 4 条测试（`BoundedReadTest`）：小图原样返回、**刚好等于上限放行**、
**超一字节拒绝**、空流返回空数组。

## 3. 低危：`image_download_client` 的名字已经名不副实  ✅ 已修（改名）

### 证据

三处调用，只有一处真在下载图片：

| 调用点 | 用途 |
|---|---|
| `api/image_output.rs:162` | 下载上游图片（原名相符） |
| `provider_loop.rs:2800` | **入口容错的地址兜底**（与图片无关） |
| `request.rs:200`（文档引用） | 同上 |

它实际是「**可钉 DNS 地址的 Client 构造器**」，`redirect(none)` 与
`resolve_to_addrs` 才是它的本质。

### 修法（已落地）

改名 `egress::pinned_address_client`（5 处引用，零行为改动）。函数文档补上
改名的理由：这个名字一旦只提图片，下一个人在 `provider_loop` 里读到时就会
另造一个同样的构造器 —— 而 `Policy::none()` 与 `resolve_to_addrs` **必须成对
出现**（少一个是安全缺口），分散成两份实现迟早走样。

## 4. 低危：轮询缺少「进度可见」与「剩余时间」提示

### 证据

`core/upstream/image_tasks.rs` 每 5 秒轮询、受 `body_ms`（默认 300 秒）总超时
约束。超时后报「生图响应超时（300秒），上游可能已消耗额度」——归因是对的
（这点要肯定），但用户在这 300 秒里**看不到任何进度**：客户端一直显示
「生成中…」，与「已经卡死」无法区分。

### 建议

- **P3**：`RequestTelemetry` 已有 `note_first_frame` 之类的钩子，可把
  「第 N 次轮询」写进请求日志行，让任务中心的进行中行能显示轮询次数。

## 5. 确认没问题的部分（逐条给了证据，不是「看着没问题」）

| 项 | 证据 |
|---|---|
| **生产代码零 panic** | 19 个新增 `.rs` 里 `unwrap/expect/panic!/unreachable!` 全部位于 `#[cfg(test)]` 之下（按 `#[cfg(test)]` 行号切分后统计为 0） |
| **SSRF 两层防线** | `image_output::public_address` 逐地址判公网（含 CGNAT 100.64/10、IPv6 ULA、6to4 映射）；`image_download_client` 用 `resolve_to_addrs` 钉死 + `Policy::none()` 逐跳自跟 |
| **下载令牌强度** | `image_assets` 用 `getrandom` 取 32 字节（256 位）十六进制；`/v1/images/files/:id` 免鉴权但令牌本身即能力凭证 |
| **缓存不会吃穿内存** | 默认 128 MiB、可配 8~4096、LRU 按 `used` 序号淘汰；`store` 在写入前拦「整批超上限」，避免刚入队就被淘汰导致链接 404 |
| **锁不跨 await** | `image_assets` 用 `std::sync::Mutex`，所有 `lock()` 都在同步块内，没有跨 `.await` 持锁 |
| **Key 作用域真实生效** | `ForwardRequest.allowed_providers` 经 `mod.rs:440` 进候选链；`resolve_model` 另有 `allows_model` 检查（404 `model_not_found`） |
| **出站 multipart 正确** | boundary 逐段检查内容撞车（撞上重拼，上限 8 次）、头部 CRLF、文件名只用自生成 ASCII 名；有一条端到端用例让真 axum `Multipart` 解析器读回逐字节比对 |
| **Gemini 流不交付半张图** | 只有 `finishReason=STOP`/`[DONE]` 才算收齐；流断无收尾直接报错 |
| **图片模型不污染对话** | `default_model_catalog()` 排除 `kind=image`；对话入口有反向门禁 |
| **客户端取消语义** | `AgateRemoteImage` 用 `LaunchedEffect(url)`、页面用 `rememberCoroutineScope`，组件/页面销毁即取消；`busy` 随 composable 一起销毁，不会留脏状态 |
| **客户端超时方向正确** | `readTimeout(330s)` 略大于内核 `body_ms`（300s），让内核先说出真实原因而不是客户端报「网络超时」 |
| **客户端不重复提交** | `submit()` 第 146 行 `if (… || busy) return`，且按钮 `enabled = canSend` 同判 |
