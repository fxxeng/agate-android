# 提供商余额接口摸排

> 依据：`agate-server` 源码（`core/providers/*/balance.rs|usage.rs`、`core/usage_query.rs`、`core/providers/custom/balance.rs`）
> 口径：**只有 `ProviderAdapter::supports_usage() == true` 的家才会出现在批量查询里**

## 2. 查询编排口径（`core/usage_query.rs`）

| 维度 | 行为 |
|---|---|
| 批量目标 | 范围内**全部可用账号**，**不看 `enabled`**（禁用只表示「转发别用它」） |
| `skipped` | 是**数量**（不可用账号个数），不是 id 数组 |
| 单查（带 `id`） | 不做能力过滤，如实报「该家不支持」 |
| 401 | 先刷新再重试一次；刷新也失败时把两句都给出（提示「登录态可能被作废，请重新登录」） |
| 并发 | 逐账号并发（`join_all`），超时由各适配器自己设（15~20s） |
| 落库 | 结果写记录表；批量/单查/自动心跳三条入口共用；低余额可触发限制器 `enforce_low_balance_disable` |
| 快照 | `/api/accounts/usage/snapshot` 供列表页直接读，不必每次现查 |

## 3. 各家的坑（实现时要注意的）

1. **codearts 两份账**：统计接口只说付费套餐；福利池在另一个网关。只读一处 → 显示假的「还有额度」。
2. **trae 两份账**：`ent_usage` 给权益包；**Free/SOLO 的额度只在 `pay_status`**。只读一处会得到 0。
3. **qoder 三桶**：`addOnQuota` 键可能整个不存在（不是 0），别 `unwrap`。
4. **catpaw 需要额外凭证**：普通 accessToken 查不到余额，要 `balanceToken`（= passport cookie 的 `token2`）；这正是「设置 → 家专属设置」里那一栏。
5. **officeace 凭证不全**：只导入了 Basic 凭据的账号会回 `usage_not_configured`，前端应显示「未配置查询」。
6. **accio 没有绝对额度**：只有百分比 + 倒计时，`available` 恒 null。
7. **cline 余额可为负**：负数 = 欠费，不要当异常过滤掉。
8. **loomy 没有余额接口**：余额藏在流水的响应摘要里，`pageSize=1` 只是拿摘要。

## 4. 与客户端的关系

- 账号行上的「积分 / 余额」按钮 → `GET /api/accounts/usage?id=<account>`（单查）
- 批量刷新 → `GET /api/accounts/usage`（批量，返回 `results[] + skipped`）
- 解析注意：`error` 字段可能是 **JSON null**（不是字符串），用 `opt()` + 类型判断，别用 `optString`（会把 null 变成 `"null"`）
- `usage` 缺失时应显示「未返回余额数据」，而不是「查询失败」
