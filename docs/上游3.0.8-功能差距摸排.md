### C-AI 助手：落地时的三处事实

1. **对话必须走端口，不能走 JNI**。`jni_bridge::api_call` 用 `to_bytes` 收完整个
   响应体才返回、还挂 120s 超时，SSE 逐字渲染无从谈起。所以这一页走真实端口 +
   OkHttp `EventSource`，代价是 **Core 态（网关未启动）下不可用** —— 页面明说并
   引导，而不是留一个永远转圈的加载态。
2. **工具定义与执行全在前端**，内核只认 `ALL_TOOL_IDS` 的 id 清单用于展开配置表。
   加工具不必动 Rust；但「前端 `TOOLS`」与「内核 `ALL_TOOL_IDS`」两处要同步，
   内核多一个前端没有的 id 会变成永远点不上的死项（`set_provider_order` 现状）。
3. **上游 9 只工具里剔除 `set_provider_order`**：本内核已刻意下线 `providerRoute`，
   账号是全局一条队列、先后由账号优先级决定，留这只工具等于给模型一个改不动东西
   的按钮。

### A-1 剩余项：思维链 / 工具调用 / 工具结果

上游文案：`<summary>思考过程</summary>`、`调用工具`、`工具结果图片`。

**结论：内核无需改动**，数据源已经存在且可读：
- 下游响应体在 `request_raw` 表（`/api/stats/requests/raw?id=` 已暴露，两侧各 128 KiB 截断）。
  **流式也会采**：`RecordingStream` 里的 `RawCapture` 逐帧抄一份客户端可见的字节，
  在流的 `settle()` 处定稿（`api/pipeline.rs:800` 起）。流式分支里那句
  `raw_response: None` 只是初值，settle 时会被覆盖 —— 别把它当成"流式不采"。
- 上游原始报文在 `debug_traffic` 表（`/api/debug/traffic?id=` 已暴露，
  `api/debug_api.rs:80`），流式存的是**上游原始 SSE**，适合对照"模型真正吐了什么"。
- 所以这是**纯客户端解析 + 展示**工作：从 SSE 文本里抽
  `reasoning_content` / `tool_calls` / `tool` 角色消息，按上游那三段折叠呈现。

需要注意的前提：**未开调试模式时两侧都不采**（同一个开关，构造时定格），
所以这段展示要能优雅地"没数据就不渲染"，而不是显示空的折叠条。

### A-4 路由预演（V44 落在设置页：`选号方式` / `候选队列` / `自愈演练` / `并发闸门`）

- 三策略：顺序优先 / 负载均衡 / 同家轮询
- 选号预演：接下来 N 个并发请求会分给谁

- 自愈策略：连续失败 N 次熔断 Ns，到点放行试一次

## C 档：上游有、Agate 完全缺（M4 取材）

- **数据报表**（`sub-reports`）：Token 消耗 / 消耗趋势 / 24h 双轴 / 365 天
  热力图 / 用量占比三维 / 环图 / Top 账号 / 提供商排名 / Top 模型 —— **已完成**。
  实现时发现一处**原稿与内核不一致**，以内核为准：
  - v44 画的时间档是「10分 / 1时 / 24时 / 7日 / 30日 / 本月」，但
    `/api/stats/summary` 的 `RANGES` 是 `today / 7 / 30 / month / all / custom`
    —— 内核按**天**聚合，没有分钟级桶。原稿是按 Node 版画的。
  - v44 的「命中率可超 100% 不夹取」是**对的**，而现成的
    `AgateDualAxisChart` 会把右轴读数 `coerceIn(0f, 1f)`，直接复用会把真实
    比值压平 —— 所以报表页自己画了双轴（右轴按真实最大值定档）。
  - 内核 `overview` 不含"输入/输出 Token 拆分"（只有 `tokens` 总量），
    所以原稿那行「输入 X · 输出 Y」没做 —— 不拿 `cache_input_tokens` 冒充。
- **出网代理池**（`sub-proxy`）：代理分组、健康检查、绑定提供商、全局代理 ——
  **已完成**（代理池管理与健康检查；账号绑定入口不在这一页，见下）。
  实现时确认的几处事实：
  - 内核 10 个端点全在（`api/proxies.rs`），本页**零内核改动**。
  - **协议只有 `http` / `socks5`**，没有 https（`normalize_item` 的校验）。
  - 新建接口**只收手动条目**：`clash` 与 `subscription` 是镜像记录，手工新建
    会被 400 拒绝（否则下次同步就把它摘掉，白填一次）。
  - 镜像条目不是不能动，而是**只能动本地禁用位**（`pool/enable` 三种来源都放行）。
    所以「来源侧本来就没开」时不给开关按钮 —— 点了不会有任何变化。
  - `GET /api/proxies/pool` **进页面就自动同步一次 Clash**（幂等），所以那一次
    不该弹提示；只有手动点「同步 Clash」才报「更新了 N 项 / Clash 不可用」。
  - 端口范围保存后内核**不回收已注册端口**，界面必须提示「需重启才完整生效」。
  - **账号 ↔ 出口的绑定不放在这一页**：它属于账号编辑弹窗（`account` 的
    proxy 字段），这一页只在条目行上显示「被 N 个账号引用」。
- **MCP**（`sub-mcp`）：授权客户端、AI 分析演示
