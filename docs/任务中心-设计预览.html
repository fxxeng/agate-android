任务中心 · 设计预览

按上游 3.0.8 的真实页面结构重排：一个签到中心（三 tab）+ 一个定时任务页，摊成 Agate 的四页

这一版先按真实上游做，不是按 v44 稿的六页。理由：上游 3.0.8 的签到中心是 一页三 tab（签到中心 / 定时签到 / 签到记录），而「周期任务」是另一个一级页， 「验证码池」在上游零 UI（是后台守卫脚本）。照六页铺会造出三个 「进去只有一个开关」的空页面。逐条依据见 docs/任务中心-上游3.0.8签到中心深挖.md。

⓿ 为什么是四页而不是六页

左边是上一版计划的六个二级页，右边是它们在上游源码里的实际位置。 红 = 上游没有对应页面。

原计划的六页上游的真实位置结论
福利中心 「签到中心」tab 里的三块面板（每日签到 / 新手福利 / 活动福利） 不是页面，是 tab 内分区
定时签到 「签到中心」的第二个 tab ✅ 真的是独立页
签到台账 第三个 tab，但形态已换：轮次台账 → 每账号明细 名字要改，内容要换
保活链 「定时签到」tab 里的一块半幅卡 不是页面，是页内一块
周期任务 另一个一级页 data-page="tasks" 不是签到中心的子页
验证码池 零 UI：zcode-captcha-pool.js 是后台守卫，无挂载点 上游没有这个页面

⓪-2 四页落位

  • ①签到中心 → 总览四格 + 每日签到 + 新手福利 + 活动福利 + 成长任务（原「福利中心」并入）
  • ②定时签到 → 总开关 + 条目 CRUD + 保活模型链（原「保活链」并入）
  • ③签到记录 → 每账号明细台账（原「签到台账」改形态改名）
  • ④周期任务 → 六条间隔任务（独立成页，与签到无关）
  • 验证码池 → 不独立成页，在任务中心首页放一张读数卡（水位 + 节奏三项）

① 任务中心（首页）：分组导航 + 验证码池读数

首页不再塞三档 seg（原来「今日 / 福利 / 定时」的分法，是把上游的三个 tab 和另一个一级页混在一起切）。现在它只做一件事：告诉你现在什么状态、往哪进。 四个入口的副标都是真实读数，不是名词解释。

⑤ 周期任务：六条间隔型

⑥ 取舍：三处不做 / 改做法

项上游 / v44 稿本版做法
验证码池「手动过码」 v44 画了「过码」按钮，弹出内嵌 WebView 滑块，通过即铸一张令牌 不做。上游本身没有这个 UI（令牌由 WebView 里的后台守卫铸）； Android 端要做需要内嵌 WebView + 阿里云 SDK，与本轮范围差得远。 只做读数 + 节奏三项，并在卡里说明令牌从哪来。
「签到台账」（轮次） v44 稿的一页：「最近 50 轮 · 每轮一条 · 失败明细前 5 条」 不单独成页。上游已淘汰这个形态；内核里两套数据都还在， 轮次只作总览卡的一个读数，明细走「签到记录」。
「福利中心」「保活链」两个独立页 v44 稿的两个二级页 合并。福利中心 → 签到中心的三块面板；保活链 → 定时签到的一块卡。 各自独立成页会让页面只剩一个开关或一个 5 行清单。

⑦ 内核就绪度

这一轮不需要改内核。全部端点已有，客户端骨架里那些「内核未暴露」的注释 是过时的（写于端点尚未补齐时）。

  • 聚合快照 GET /api/checkin-center —— 一次拉全，零上游请求
  • 定时条目 GET/POST /api/checkin-schedules、{id}/delete、{id}/run
  • 记录明细 GET/DELETE /api/checkin-records —— 真分页 + 四筛选 + all=1 护栏
  • 周期任务 GET /api/scheduled-tasks、PATCH {id}、POST {id}/run
  • 保活链 GET/POST /api/checkin-keepalive
  • 新手福利 GET /api/accounts/{id}/onboarding?refresh=1、POST …/onboarding/claim
  • 成长任务 GET …/growth、POST …/growth/task|school|travel
  • 套餐 POST …/zcode-claim/preview、…/zcode-claim
  • 验证码池 GET /api/zcode/captcha、GET/PUT /api/zcode/captcha-pool
  • 单账号签到 POST /api/accounts/checkin body {id}； 国际版三档 POST /api/checkin-activity body {id, mode}

⑧ 待你拍板

  • 四页 vs 六页 —— 推荐四页（本文档结构）。坚持六页也能做，但福利中心与保活链会明显偏空。
  • 签到记录 vs 签到台账 —— 推荐跟随上游：明细为主、轮次降为读数。 若更想保留轮次视角，可以在记录页加一档 seg 切换（工作量约 +1 页）。
  • 验证码池 —— 推荐只做读数 + 节奏设置，「手动过码」留空位并标注原因。 若一定要过码，那是另一个量级的活（WebView + 阿里云 SDK）。
